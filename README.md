# MRI — веб-приложение для обработки МРТ-изображений

## Сегментация изображений с использованием YOLOv8n-seg

Учебное веб-приложение на **Flask** для загрузки и автоматической обработки МРТ-изображений с использованием предварительно обученной модели `YOLOv8n-seg`.

Приложение позволяет загрузить одно или несколько изображений, выполнить инференс модели, визуализировать найденные объекты в виде масок/контуров и ограничивающих рамок, сохранить метаданные обработки в **SQLite**, просмотреть историю результатов и экспортировать её в **Excel**.

> **Важно:** используемые веса `yolov8n-seg.pt` являются предварительно обученной моделью и не являются специализированными медицинскими весами, обученными именно на датасете МРТ опухолей. Поэтому проект следует рассматривать как учебный/экспериментальный прототип, а его результаты — не как медицинское диагностическое заключение.

## Возможности

- веб-интерфейс на Flask без использования `tkinter` и консольного диалога выбора папок;
- загрузка одного или нескольких изображений за один раз;
- поддержка форматов `JPG`, `JPEG`, `PNG`, `BMP`, `TIFF`, `TIF`;
- ограничение размера HTTP-запроса до 16 МБ;
- автоматическая обработка изображений с помощью `YOLOv8n-seg`;
- получение ограничивающих рамок, классов, оценок уверенности и масок сегментации;
- выделение найденных областей на изображении зелёными контурами и рамками;
- сохранение исходных и обработанных изображений в отдельных директориях;
- автоматическое добавление уникального префикса к загруженным файлам во избежание конфликтов имён;
- сохранение истории обработки в базе данных SQLite;
- выдача истории результатов через JSON API;
- экспорт накопленной истории в отдельный файл Microsoft Excel (`.xlsx`);
- отображение последних результатов и общей истории обработки в браузере.

## Стек технологий

- **Python** — серверная логика;
- **Flask** — веб-сервер и маршрутизация;
- **Ultralytics YOLO** — запуск модели `YOLOv8n-seg`;
- **OpenCV** — чтение, преобразование и сохранение изображений, извлечение контуров;
- **NumPy** — работа с массивами изображений и масок;
- **SQLite** — хранение истории обработки;
- **openpyxl** — формирование Excel-отчёта;
- **HTML/CSS + Jinja2** — пользовательский интерфейс.

## Требования

Перед запуском необходимо установить Python и зависимости проекта.

Основные библиотеки:

```bash
pip install flask ultralytics opencv-python numpy openpyxl werkzeug
```

Также необходимо наличие файла модели:

```text
yolov8n-seg.pt
```

Файл модели должен находиться в корневой директории проекта рядом с `app.py`.

## Структура проекта

Примерная структура каталогов:

```text
MRI/
├── app.py
├── yolov8n-seg.pt
├── segmentation_results.db
├── templates/
│   └── index.html
└── static/
    ├── uploads/
    └── results/
```

Назначение основных компонентов:

- `app.py` — серверная логика, обработка изображений, работа с БД и экспортом;
- `yolov8n-seg.pt` — файл весов модели;
- `templates/index.html` — веб-интерфейс;
- `static/uploads/` — загруженные исходные изображения;
- `static/results/` — обработанные изображения;
- `segmentation_results.db` — локальная база данных SQLite.

## Установка и запуск

1. Клонировать репозиторий или скачать исходный код проекта.

```bash
git clone https://github.com/PunchGott/MRI.git
cd MRI
```

2. Установить зависимости:

```bash
pip install flask ultralytics opencv-python numpy openpyxl werkzeug
```

3. Убедиться, что в корне проекта находится модель:

```text
yolov8n-seg.pt
```

4. Запустить приложение:

```bash
python app.py
```

5. Открыть в браузере:

```text
http://127.0.0.1:5000
```

## Сценарий работы

1. Пользователь открывает веб-приложение.
2. Выбирает одно или несколько изображений.
3. Нажимает **«Загрузить и обработать»**.
4. Flask принимает файлы и сохраняет их в `static/uploads/`.
5. Для каждого изображения запускается `YOLOv8n-seg`.
6. Из результатов модели извлекаются рамки, классы, уверенности и контуры масок.
7. Обработанное изображение сохраняется в `static/results/`.
8. Метаданные обработки записываются в `segmentation_results.db`.
9. Результаты отображаются в веб-интерфейсе.
10. При необходимости история обработки экспортируется в Excel.

## Параметры обработки

В текущей реализации модель запускается с параметрами:

```python
imgsz=640
conf=0.25
```

Для построения контуров маска переводится в бинарный вид с порогом `0.5`, после чего внешние контуры извлекаются средствами OpenCV.

## База данных

Для хранения истории используется SQLite-таблица `segmentation_results`.

В ней сохраняются, в частности:

- идентификатор записи;
- имя изображения;
- путь к исходному файлу;
- дата и время обработки;
- количество обнаруженных объектов;
- время инференса;
- ограничивающие рамки;
- значения уверенности;
- контуры сегментации;
- использованная модель.

### Очистка истории

Чтобы удалить все записи из таблицы, не удаляя сам файл базы данных:

```sql
DELETE FROM segmentation_results;
```

При необходимости можно также сбросить счётчик `AUTOINCREMENT`:

```sql
DELETE FROM sqlite_sequence WHERE name = 'segmentation_results';
```

Для полного пересоздания БД можно удалить файл `segmentation_results.db` и снова запустить приложение.

## HTTP-маршруты

| Метод  | Маршрут               | Назначение                             |
| ------ | --------------------- | -------------------------------------- |
| `GET`  | `/`                   | Главная страница и история обработки   |
| `POST` | `/upload`             | Загрузка и обработка изображений       |
| `GET`  | `/uploads/<filename>` | Получение исходного изображения        |
| `GET`  | `/results/<filename>` | Получение обработанного изображения    |
| `GET`  | `/api/results`        | История обработки в формате JSON       |
| `GET`  | `/export/xlsx`        | Формирование и скачивание Excel-отчёта |

## Экспорт в Excel

Маршрут `/export/xlsx` формирует отдельный файл вида:

```text
segmentation_report_YYYYMMDD_HHMMSS.xlsx
```

Отчёт содержит два листа:

- **«Сводка»** — количество обработанных изображений, общее число объектов, среднее время обработки и использованная модель;
- **«Результаты»** — подробная информация по каждой обработке, включая рамки, уверенности и контуры сегментации.

## Ограничения проекта

- текущая модель не специализирована под медицинские МРТ-данные;
- качество сегментации зависит от используемых весов модели и входных изображений;
- результаты проекта не предназначены для клинического применения;
- приложение рассчитано на обработку изображений, а не на работу с полноценными медицинскими форматами и трёхмерными МРТ-исследованиями;
- SQLite используется как локальное хранилище истории и не предназначен здесь для высоконагруженного многопользовательского режима.
